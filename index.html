            Cloud settings

            Connect the subject cloud to a GitHub repository so uploaded files reach every student device, then decide how counters and student records behave.

            How sharing works: a browser can never write to GitHub by itself, so it talks to the shared Supabase backend below using the publishable key — that makes registration, sign-in, the visitor counter and the download counter identical on every device. A GitHub Action then mirrors the shared register into data/cloud-data.json, so the repository holds the class list too. The GitHub token saved here only publishes files; it is never shared with visitors.

            Access token

            A GitHub fine-grained personal access token with Contents: Read and write for this repository only.

            Not saved

            Create it on GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens. Repository access: only this repository. Permissions: Contents: Read and write. Open GitHub token page

            Forget the token when this browser tab closes (safer on shared computers)
            Revoke on GitHub

            The token stays in this browser's local/session storage and is sent only to api.github.com. It is never written to the HTML or repository. Do not put it in cloud-data.json or a hidden admin field: this public static site is delivered to every visitor, and a Contents: write token could change or delete repository files. Shared access must use a server-side secret.

            Cloud location

            Where uploaded files and the resource list are stored.

            Files are published here, e.g. resources/Year 12/…

            Holds sync-config.json (the public Supabase URL and key) and cloud-data.json (the register mirror). In a public repository anyone can read them.

            Shared cloud sync Supabase

            Share student registration, sign-in, the visitor counter and the download counter across every device.

            Not configured

            Only the publishable key (sb_publishable_… or the legacy anon JWT) belongs here — it is designed to be public because Row Level Security blocks direct table access and only the madv_* functions are exposed. Never paste a sb_secret_… key or a GitHub token. Saving writes just the URL and key to data/sync-config.json, so every device connects automatically.

            How the sharing works

            1. Create a GitHub repository and enable GitHub Pages for it (Settings → Pages → Deploy from branch).
            2. Upload this single index.html file to the repository — one file is the whole website.
            3. Sign in as administrator (or admin), create a fine-grained token with Contents: Read and write, then paste and Save access token here.
            4. Upload resources from the Upload Resource page. Files are committed to the repository and listed in library.json.
            5. Share the GitHub Pages link with students. They register with a first name and year level, then download files with the username and password the site gives them.
            6. Open the Admin dashboard to monitor registrations, visits and downloads, and to export CSV reports.
